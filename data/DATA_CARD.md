## 3. ファイル形式とパース上の注意

| 項目 | 実態 | 対処 |
|---|---|---|
| 文字コード | **CP932 (Shift_JIS)** | `encoding="cp932"` |
| 1行目 | タイトル行（`7地価公示地価データ一覧,,,...`） | `skiprows=1` |
| 2行目 | 実際のヘッダ | — |
| 数値形式 | `'3,960,000 '`（カンマ＋**末尾スペース**） | `src/cleaning.py::to_number` |
| 全角数字 | 一部に `１２３` 形式 | 全角→半角に変換してからパース |
| 括弧 | 公示は `交通施設までの道路距離（m)`（**開き全角・閉じ半角**）、基準地価は `（m）` | `data_loader._normalise_name` で括弧を全角に統一 |
| 和暦表記 | `kouji_r7`〜`kijun_r7` は `'7 '`、**`kouji_r8` のみ `'令和8年'`** | `src/cleaning.py::parse_wareki_year` が両対応 |
| 階数 | `'10F'` / `'1B'`（地下） | `parse_floor_count`。地下は負値で表現 |
| 空欄 | `''`（空文字）と欠損が混在 | 統一して `NaN`。カテゴリ列は文字列 `"unknown"` を明示的なカテゴリとして扱う |

## 4. 列の意味（主要列）

`data_loader.COLUMN_MAP` が和文列名を ASCII 識別子へ変換します。代表的な対応:

| 和文列名 | 内部名 | 意味 |
|---|---|---|
| 都道府県市区町村コード | `admin_code` | 市区町村コード（例 13101 = 千代田区） |
| 対象年（和暦） | `year` | 西暦に変換して保持 |
| 標準地名 / 基準地名 | `locality` | 地域名 |
| 標準地番号（用途） | `use_code` | 用途コード（地点番号の一部） |
| 標準地番号（連番） | `seq_no` | 連番（地点番号の一部） |
| 区市町村名 | `municipality` | 区市町村 |
| 当年価格（円） | `price_current` | **地点全体の価格（総額）** ← そのまま目的変数にはしない |
| 前年価格（円） | `price_previous` | 前年価格。**強いリーク源** |
| 対前年変動率（％） | `change_rate_prior_year` | **強いリーク源** |
| 地積（㎡） | `site_area` | 土地面積 |
| 間口（比率）/ 奥行（比率） | `frontage_ratio` / `depth_ratio` | 形状 |
| 前面道路の幅員(m) | `road_width` | 接道幅員 |
| 交通施設までの道路距離（m） | `station_distance` | 最寄駅からの道路距離 |
| 用途区分 | `use_district` | １低専／商業／準工 など |
| 指定建蔽率（％）/ 指定容積率（％） | `bcr` / `far` | 都市計画の指定値 |
| 利用の現況 / 構造 / 地上階 / 地下階 | `current_use` / `structure` / `floors_above` / `floors_below` | 建物属性 |

### 4.1 目的変数の定義

```
unit_price (円/㎡) = 当年価格（円） ÷ 地積（㎡）
```

**理由**: `当年価格（円）` は地点の**総額**です。総額を目的変数にすると
「面積が大きいほど高額」という自明な関係を当てるだけのモデルになり、
土地の評価特性を学習したことになりません。

実測した相関係数（`kouji_r8`、n=2,560、ピアソン）:

| ペア | 相関 |
|---|---|
| 地積 ↔ 当年価格（総額） | **+0.053** |
| 地積 ↔ 平米単価 | **−0.038** |

総額を目的にすると面積との相関が正（広いほど高い）になるのに対し、
平米単価にすると負（広い土地は㎡あたり割安）になり、不動産として自然な方向になります。
この関係は `tests/test_features.py::TestTarget` で検証しています。

なお相関の絶対値自体はどちらも小さく、東京都の標準地は面積のばらつきが
小さい（中央値 164㎡、IQR 120–230㎡）ことが理由です。それでも
「総額＝面積 × 単価」という恒等関係を目的変数から外しておくことが、
モデルの解釈性のために重要です。

## 5. クロス年度リンク（パネル化）

同一地点は次の複合キーで年度をまたいで対応が取れます。

```
site_key = 都道府県市区町村コード | 標準地番号（用途） | 標準地番号（連番）
```

| 組み合わせ | キーが一致する地点 | そのうち価格が完全一致 | キーが一致しない地点 |
|---|---|---|---|
| 地価公示 令和7年 → 令和8年 | 2,518 / 2,560（**98.4%**） | 2,518（**100%**） | 42（新規選定） |
| 基準地価 令和6年 → 令和7年 | 1,277 / 1,280（**99.8%**） | 1,277（**100%**） | 3（新規選定） |

- キーが一致しない地点は、新規に選定された標準地です（令和8年ファイルでは前年価格が空欄）。
- キーが一致した地点については、**前年価格が前年の当年価格と1円の狂いもなく一致**します
  （最大絶対差 0 円で検証済み）。年度をまたぐパネル化が正しく機能する根拠です。
- **注意**: この一致は「地点キーで整列してから比較した場合」の値です。
  2ファイルの**並び順は年度間で同一ではない**ため、
  **行番号でそのまま比較すると一致率は 42% にしかなりません**。
  これは開発中に実際に踏んだ罠です（`docs/INTERVIEW_GUIDE.md` 7.2 に記録）。
- 年をまたぐラグ特徴量 `lag_unit_price` は、このキー結合で**実測値として**取得します。
  ファイル内の `前年価格` 列をそのまま特徴量に使うことはしません（リーク防止のため）。

## 6. 既知の制約（正直な記載）

1. **地価であって取引価格ではない。** 公示地価・基準地価は不動産鑑定士の評価額であり、
   実際の売買価格ではありません。実際の成約価格を知りたい場合は不動産取引価格情報
   （国土交通省）が必要ですが、API キーが必要で再現性が下がるため本プロジェクトでは使いません。
2. **東京都のみ。** 他道府県は含みません。地方の価格水準には一般化しません。
3. **地点数が限られる。** 1年あたり 2,560 地点（公示）／1,280 地点（基準地価）。
   東京都内の全土地を代表する標本ではなく、**評価の基準となる標準的地点**の集合です。
4. **公示は年1回。** 地価公示は毎年1月1日時点、基準地価は毎年7月1日時点の評価で、
   年1回しか更新されません。月次・四半期の予測は原理的にできません。
5. **極端な外れ値が実在する。** 八王子市美山町の山林（3,285㎡・1,560円 = 0.47円/㎡）から
   千代田区の商業地（13万円/㎡超）まで 5 桁の幅があります。これは**データの誤りではなく
   実際の土地用途の多様性**です（`利用の現況 = 山林（雑木林）`、`森林法 = 地森計`）。
   削除せず、対数変換と地点属性で扱います。
6. **同一地点の反復計測。** パネル化すると同一地点が複数年に現れます。本プロジェクトは
   地点単位で train/val/test を分離し、同一地点が学習と評価に同時に現れないようにしています。
7. **`用途区分` が空欄の地点が存在する**（公示 令和8年で 34 地点）。山林・農地などで、
   モデル上は `"unknown"` という明示的なカテゴリとして扱います。

## 7. 再取得する場合

東京都オープンデータカタログ（https://catalog.data.metro.tokyo.lg.jp/）で
「地価公示」「基準地価」を検索し、東京都財務局が公開する CSV を取得してください。
本プロジェクトのコードは列名（和文ヘッダ）に依存しているため、列構成が変わった場合は
`src/data_loader.py::COLUMN_MAP` の更新が必要です。
